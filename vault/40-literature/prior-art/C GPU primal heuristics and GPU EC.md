# Prior art C — GPU primal heuristics for MIP and GPU evolutionary computation

Sweep date 2026-10-05. Question asked of each work: what runs on the GPU (LP, propagation, local search, a population),
for which problem class, against which baselines, and does it exchange solutions with an exact solver?

**Rank names** follow the vault ([[D-004 Mapping I-TREA (2015) to I-TREA II]]): **Rank 0 = infeasible good** (the
brief's "R2"), **Rank 1 = feasible good**, protected (the brief's "R1"), **Rank 2 = rejects** (the brief's "R3").

**Sources and rules** as in [[A Constraint handling with infeasible solutions]]. Source code is cited at a pinned
commit. Verification levels: *Full text read*, *Abstract / landing read*, *Metadata only*.

## 2. What this means for I-TREA II

- **A GPU MIP population already exists.** cuOpt's population (`nvidia2026cuoptsrc`, presented at MIP 2025 by
  `corduk2025evoframework`) holds feasible and infeasible solutions, protects the single best feasible in slot 0, ranks
  infeasible members by bandit-weighted violation, recombines with bandit-chosen operators, and takes solutions from its
  own concurrent CPU B&B. CHAP pools feasible and infeasible candidates across GPU and CPU heuristics. So neither "a GPU
  population for MIP" nor "solver → population inflow" may be presented as new.
- **The defensible differences** (stated against cuOpt, the closest system): (a) an explicit cap of ⌊x·P⌋ on infeasible
  members **whose key beats the incumbent** (Rank 0), where cuOpt's weight rule actively keeps the best infeasible member
  behind the best feasible; (b) protection of the top ⌈y·#feasible⌉ feasible (Rank 1), not just the single best;
  (c) two-way exchange with an **external** general solver (SCIP, HiGHS), with the EA's better incumbents handed back
  as starting points; (d) parametric operators under a pre-registered protocol ([[D-002 Pre-registration — hypotheses, arms, analysis]]).
- **Baselines.** cuOpt heuristics-only is the obvious ablation baseline for the population itself (arm A6); A2
  (SCIP‖cuOpt) is already the primary control. Since September 2026 the CPU side has strengthened: ReXi / concurrent
  SCIP (`mexi2026rexi`) and a patched HiGHS with FJ, FPR and LocalMIP (`spoorendonk2026highsheur`). CHAP's code is not
  released; PaNGEA is a preprint of 2 Oct 2026.
- **Operators.** The repair layer is in the FJ / Local-MIP family (`luteberget2023feasibility`, `lin2024localmip`);
  batched bound propagation (`sofranac2022domainprop`) and PDLP-guided fix-and-propagate (`kempke2025fixprop`) are the
  GPU building blocks for LP-guided seeding and repair, the latter already shown on unit-commitment-scale models.
- **GPU speed-up claims** from classic GPU GA papers (`pospichal2010cudaga`) are for tiny continuous problems against one
  CPU thread; they set no expectation for MIP.

## 3. Negative searches (verbatim from the sweep; later corrections in italics)

1. "GPU genetic algorithm cooperating with MIP solver exchange incumbent solutions hybrid": the only GPU MIP hit was CHAP (a heuristic portfolio; it does not hand incumbents to an exact solver); the rest were problem-specific CPU GA+MIP hybrids. Apart from cuOpt's internal population, which takes B&B and CPU-FJ solutions, I found no GPU EA that exchanges solutions both ways with an external SCIP/HiGHS/Gurobi B&B.
2. "GPU evolutionary algorithm mixed integer infeasible solutions archive MIPLIB population": found no MIP-specific GPU EA with a capped-fraction rank of super-optimal infeasible solutions. Nearest: the cuOpt population (infeasibility-weighted quality, best-feasible slot 0), CHAP's partial-solution pool (guidance only) and GMPEA (arXiv:2509.19821, GPU constrained multi-objective EA on EvoX, not MIP).
3. "ParaLS parallel local search mixed integer programming": no MIP solver by that exact name. The parallel LS works from Cai's group are ParaILP (IJCAI 2024, ILP) and ParLS-PBO (CP 2024, pseudo-Boolean).
4. "ViolationLS" open preprint (arXiv / Google Research / author page): none found; only the Springer/ACM version and a ResearchGate entry, so it is marked paywalled_only.
5. "feasibility jump GPU parallel implementation batched": no separate GPU-FJ paper beyond the cuOpt paper (arXiv:2510.20499) and PaNGEA. One hit was a GitHub issue in an unrelated project (thegoodengineers/SANKHYA), which is not citable.
6. "Janssen GPU island model genetic algorithm CUDA": Concurrency and Computation: Practice and Experience 2022 (DOI 10.1002/cpe.6286) is Wiley paywalled, and no open copy was verified, so it is not included.
7. "NVIDIA cuOpt MILP technical report": no cuOpt MIP report beyond arXiv:2510.20499. The MIP 2025 talk 'GPU-Accelerated Evolutionary Framework for Primal Heuristics' has an abstract only, with no paper and no slides link.
8. OpenReview copy of the cuOpt paper (openreview.net/forum?id=JtwE7RMyFR): blocked by a bot check, so its venue/workshop is unverified. *(The verifier later confirmed the ScaleOpt workshop poster via neurips.cc.)*
9. Cantú-Paz island-model reports on OSTI: the hit (UCRL-JC-137169) is about selection intensity with generation gaps, not island migration, so it was not used.
