## 2. Three primal-integral definitions that disagree

Do not conflate these in the protocol, the code or the paper. Notation: x_opt (or x*) is the optimal or reference
solution, x(t) the incumbent at time t, T the budget.

**(a) Berthold 2013** (`berthold2013primal`, Defs. 2.1–2.3, from the ZIB-Report itself). Primal gap
γ(x) = 0 if c·x_opt and c·x are both 0; γ = 1 if c·x_opt · c·x < 0; otherwise
γ = abs(c·x_opt − c·x) / max{abs(c·x_opt), abs(c·x)}. A footnote treats γ ≤ 1e-6 as optimal. p(t) = 1 before the first
incumbent, then γ(incumbent). P(T) = ∫₀ᵀ p(t) dt, unnormalised; P(T)/T is the "average solution quality".

**(b) MIPfeas** (`bussieck2026mipfeas`, results in `mittelmann2026mipfeas`). Same relative gap, but **2** with no
incumbent, 1 on sign mismatch, 0 if both values are below 1e-6 in absolute value; divided by T, so P ∈ [0, 2];
aggregated by a shifted geometric mean with shift 0.001. 233 feasible MIPLIB 2017 benchmark instances, 600 s,
24 threads, one run each. The results page writes the denominator as max(abs(z(t)), abs(z*), 1), the blog without the 1
— check `create_primalintegral.py` before computing a comparable number.

**(c) ML4CO** (`gasse2022ml4co`). Absolute, unnormalised: ∫₀ᵀ c·x*_t dt − T·c·x*, with a trivial initial solution
always supplied; also a dual integral and a primal-dual gap integral ∫₀ᵀ (c·x*_t − z*_t) dt.

**D-002 today** pre-registers (a) normalised by T ("mean relative gap … 1 before the first incumbent"), aggregated as a
per-instance mean relative gain with a Wilcoxon test and bootstrap interval. The sweep's recommendation (not a
decision): report (b) as well, because a published GB10 cuOpt baseline exists under it (0.0393), and keep (a) for
comparability with the SCIP literature. On open instances the reference is the pinned solufile's best-known value, and
the integral is relative to it; the confined primal integral (`berthold2021confined`) removes the need for a reference.
This is an open question in [[Prior art]] §5; D-002 allows amendment before the first confirmatory run.

## 3. Load-bearing facts for the design

- **Feasibility test.** MIPLIB's checker accepts a_i·x − u_i ≤ 1e-5 · max{(a_i·x)⁺, (a_i·x)⁻, abs(u_i), 1}; integrality
  is an absolute 1e-4 (`gleixner2021miplib` §4.7). Use exactly this to decide whether an individual is feasible (Rank 1
  eligible) or infeasible (Rank 0 / Rank 2) before posting a solution to the solver or claiming an improvement.
  Submitted solutions are re-checked and their values recomputed exactly with SoPlex.
- **Status lists are versioned.** Pin `open-v30.test`, `hard-v31.test`, `easy-v19.test` and solufile 37 (all
  2026-09-24) in the repository; statuses move with every release.
- **Submitting** improved incumbents: miplibsolutions@zib.de. The latest release shows 51 better incumbents, so
  improvements on hard (not only open) instances are accepted. Nothing is submitted without Berk's explicit yes.
- **Published GB10 baseline** (`mittelmann2026mipfeas`): cuOpt 26.08 on a GB10 — 226/233 feasible, shifted geometric
  mean of the MIPfeas integral 0.0393; HiGHS 1.15.1 0.0453 and SCIP 10.0.1 0.0755 (Intel Core Ultra 9 285K); ReXi
  0.0165; the virtual mean commercial solver 0.0105. Note the single-run protocol.
- **Shifted geometric mean.** Achterberg 2007 App. A.3: (Π max{v_i + s, 1})^{1/k} − s, s = 10 (time), s = 100 (nodes);
  MIPfeas uses s = 0.001 on the [0, 2] integral.
- **Statistics.** Wilcoxon signed-rank on per-instance paired metrics (`demsar2006`, `derrac2011`), bootstrap intervals
  on aggregates (`dicicco1996bootstrap`), performance profiles (`dolan2002profiles`) read pairwise (`gould2016note`).
  Multiple seeds because of performance variability (`fischetti2014erraticism`); bet-and-run / multi-seed racing is a
  cheap baseline. Bartz-Beielstein et al. (2020) is the checklist.
- **Unit commitment.** PGLib-UC v19.08 (cite the version and the original sources per its README); Knueven et al.'s
  formulation; UnitCommitment.jl's independent checker for EA-produced UC solutions; Kempke & Koch (2026,
  [[C GPU primal heuristics and GPU EC]]) report UC-based models where commercial solvers find no feasible solution in
  two days.
